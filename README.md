# Gift Offer Bot

Telegram Business-бот для создания офферов на коллекционные подарки,
обновления карточек и ведения журнала событий. Python 3.11+,
SQLite, long polling. Сторонних зависимостей для запуска нет.

Бот фиксирует предложения и заявления участников. Он **не принимает и не
проверяет оплату**, не предоставляет эскроу и не переводит подарки через API.
`stars` и `gram` — обозначения цены, а не подключённые платёжные системы.

## Запуск в Docker Compose

Нужны Docker Engine и Docker Compose с командой `docker compose`.

1. Распакуйте проект и перейдите в его каталог.
2. Если `.env` отсутствует, скопируйте `.env.example` в `.env`.
   Не перезаписывайте существующий `.env` при обновлении.
3. Укажите `BOT_TOKEN`. Для новой установки задайте собственный `ADMIN_PROMO`.
4. Проверьте конфигурацию и запустите сервис:

```bash
docker compose config --quiet
docker compose build
docker compose run --rm --no-deps bot python bot.py --check
docker compose up -d
docker compose logs -f --tail=100 bot
```

`--check` проверяет формат настроек без обращения к Telegram. Он не проверяет
действительность токена, права бота или доступность сети.

Рабочая SQLite хранится в `./data`, смонтированном в `/app/data`.
Compose намеренно задаёт `DB_PATH=/app/data/offers.sqlite3` и `PORT=3000`
поверх значений `.env`. Если старая база находится в другом месте,
перенесите её вместе с WAL/SHM после остановки старого процесса либо измените
привязку тома и `DB_PATH` согласованно.

Health endpoint доступен только с хоста:

```bash
curl -f http://127.0.0.1:3000/readyz
docker compose ps
```

Для другого порта на хосте измените `HEALTH_PORT` в `.env`.
Внешний HTTP-доступ и webhook для работы бота не требуются.

```bash
docker compose stop
docker compose up -d --build
```

Одновременно должен работать **один процесс на токен**. Не запускайте локальную
копию параллельно контейнеру. При старте бот отключает существующий webhook,
сохраняя очередь обновлений. Политика `restart` перезапускает завершившийся
контейнер; статус `unhealthy` сам по себе не вызывает перезапуск.

## Локальный запуск

```bash
python --version
python bot.py --check
python bot.py
```

`.env` читается из каталога проекта; уже заданные переменные окружения имеют
приоритет. Относительный путь базы считается от каталога проекта.
`requirements.txt` оставлен как явное указание отсутствия runtime-зависимостей.

## Настройки

| Переменная | По умолчанию в коде | Назначение |
| --- | --- | --- |
| `BOT_TOKEN` | нет | Токен бота; обязательный |
| `API_TOKEN`, `TELEGRAM_BOT_TOKEN` | нет | Резервные имена токена, если предыдущие пусты |
| `BOT_NAME` | `Gift Offer` | Имя, от 1 до 64 символов |
| `ADMIN_PROMO` | `/ClezzyKryt` | Команда активации первого администратора; смените для новой установки |
| `DEFAULT_LANGUAGE` | `ru` | `ru`, `en`, `zh`, `ar` |
| `OFFER_TTL_SECONDS` | `21600` | Время ожидания оффера: 60–86400 секунд |
| `CREATE_COOLDOWN_SECONDS` | `3` | Пауза между созданием офферов: 0–60 секунд |
| `DB_PATH` | `data/offers.sqlite3` | Путь к SQLite; при пустом значении используется `DATA_DIR` |
| `DATA_DIR` | `data` | Каталог базы при пустом `DB_PATH` |
| `PORT` | `3000` | HTTP-порт 0–65535; 0 отключает HTTP локально |
| `EVENT_CHAT_ID` | `0` | ID группы событий, неположительное число; 0 отключает уведомления |
| `NFT_TRANSFER_THREAD_ID` | `0` | ID темы для событий передачи подарков |
| `NEW_OFFER_THREAD_ID` | `0` | ID темы для новых офферов |
| `HEALTH_PORT` | `3000` в Compose | Порт HTTP на хосте; самим приложением не читается |

Для уведомлений требуются одновременно ненулевые `EVENT_CHAT_ID` и ID нужной
темы. Значения ID тем: от 0 до 2147483647.

Не публикуйте `.env`, SQLite и её резервные копии. Они содержат конфигурацию
и пользовательские данные. Образ собирается только из `bot.py` и Python-модулей
пакета; рабочие настройки и данные внутрь образа не копируются.

## Использование

Включите Business/Secretary Mode бота в BotFather и подключите бота
к своему аккаунту через настройки чат-ботов Telegram. Бот проверяет
активность подключения и право ответа. Удаление исходных команд требует
соответствующих прав и выполняется после подтверждённой доставки карточки.

Из подключённого аккаунта в личном чате с владельцем подарка:

```text
.buy https://t.me/nft/DurovsCap-1234 500 stars
.buy https://t.me/nft/DurovsCap-1234 10.5 gram en
.status
.cancel
```

Язык последним аргументом необязателен. Stars допускает только целую сумму;
Gram — до девяти десятичных знаков. Ссылки принимаются в формате
`https://t.me/nft/Collection-123`, без query-параметров и фрагмента.

В личном чате с ботом доступны `/start`, `/help`, `/terms`, `/paysupport`.
Подключённый владелец может отправить команду `ADMIN_PROMO` для первичного
закрепления администратора. Повторно забрать уже занятый доступ нельзя.
Администратору доступны `/admin`, `/logs`, `/visits`, `/transfers` и настройка
аккаунта для передачи. Время в журнале показано по Москве.

### Ограничения существующего поведения

- Кнопка передачи открывает ссылку на **получателя, заданного администратором**,
  а не автоматически на покупателя оффера.
- Текст принятого оффера сообщает «успешно продан» и предлагает передать подарок
  для зачисления оплаты, хотя подтверждения платежа в коде нет. Это несоответствие
  интерфейса фактическим возможностям; в рамках рефакторинга текст сохранён.
- Часть текстов задана непосредственно по-русски, даже при другом языке оффера.
- Нажатия кнопок фиксируют заявления участников; служебные события Telegram
  записываются отдельно. Они не подтверждают оплату.
- SQLite вызывается синхронно внутри event loop, обработка событий сериализована.
  Проект не рассчитан на горизонтальное масштабирование несколькими процессами.

## Хранение и резервные копии

Схема создаётся при открытии базы; включены WAL и внешние ключи. Сохраняются
офферы, подключения, профили, журналы, настройки и offset очереди обновлений.
При неизвестном результате отправки сообщения код избегает слепого повтора.

Простой способ резервного копирования — остановить все процессы, работающие
с этой базой, и скопировать **весь** каталог данных:

```bash
docker compose stop
mkdir -p backups
cp -a data "backups/data-$(date +%Y%m%d-%H%M%S)"
docker compose start
```

Не удаляйте `offers.sqlite3-wal` и `offers.sqlite3-shm` как «мусор»:
WAL может содержать ещё не перенесённые в основной файл изменения.
Для восстановления остановите бот, сохраните текущую копию каталога,
восстановите резервный `data` и запустите сервис. Каталог должен быть доступен
контейнеру на запись. Существующая модель пользователя Docker-образа сохранена:
контейнер запускается от root.

## Структура

```text
bot.py                       запуск, polling, shutdown, HTTP-проверки
gift_offer/
  config.py                  загрузка и валидация настроек
  domain.py                  парсинг команд и переходы состояний
  service.py                 сборка компонентов, маршрутизация и общая блокировка
  models.py                  типизированные контракты записей и Telegram payload
  services/
    context.py               зависимости и состояние компонентов
    connections.py           подключение, проверка и кэш бизнес-аккаунтов
    notifications.py         ответы и уведомления
    offers.py                создание офферов и команды владельца
    actions.py               проверки кнопок и переходы состояний
    cards.py                 обновление карточек и удаление команд
    administration.py        личные команды, доступ и настройка получателя
    gifts.py                 учёт событий передачи подарков
    common.py                общие функции представления и проверки
  store.py                   SQLite и журнал событий
  telegram.py                транспорт Telegram, обработка ошибок и повторов
  views.py                   формирование карточек и клавиатур
  translations.py            локализованные шаблоны сообщений
  admin.py                   представления административного раздела
  ui.py                      кнопки, суммы и emoji
  types.py                   интерфейс транспорта и состояние health endpoint
tests/test_bot.py           исходные 130 регрессионных тестов
tests/test_composition.py   проверки связей и состояния компонентов
```

`views.TEXT` сохранён как совместимый экспорт таблицы переводов.

## Проверки и стиль

```bash
python -m unittest discover -s tests -v
ruff check .
ruff format --check .
```

Для запуска бота и тестов Ruff не нужен. Для разработки установите его отдельно:
`python -m pip install ruff==0.17.4`.
Правила импортов, линтера и форматтера находятся в `pyproject.toml`.
Тесты используют подменённый API и временные базы, без реального токена и платежей.

HTTP-маршруты:

- `/` и `/health`: HTTP 200, JSON содержит состояние готовности.
- `/healthz` и `/readyz`: HTTP 503 до подключения или если последний успешный
  polling был 90 секунд назад и более; иначе HTTP 200.
- Неизвестные пути: HTTP 404.
